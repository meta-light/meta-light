# X Posts

Turn research into posts people read and share. The analysis rules come from the research-writing skill; this skill covers the X format.

Read `../research-writing/references/style.md` for voice, terminology and number formatting. It applies here too, with the format rules below on top. For hook craft and reach mechanics, the x-algo skill can help.

## Pick the type

| Request | Type | Length |
| --- | --- | --- |
| Promote a published report or flash note | Report thread | 5 to 10 posts |
| Timely take not tied to a report | Insight thread | 5 to 8 posts |
| One observation with a number | Single post | 1 post, under 280 characters if possible |
| Long-form piece published natively on X | Article | 1,000 to 2,500 words |

Templates and examples for each are in `references/templates.md`.

## Format rules

- Number thread posts `1/`, `2/` and so on. No "🧵" or "Thread:" prefix.
- Each sentence on its own line, with a blank line between sentences.
- One idea per post.
- Bulleted lists are fine for traction metrics or catalysts. Use `-` bullets.
- Keep each post within the character limit the account has (280 for standard accounts). Check the longest post.
- Tag protocols and people with @handles only when the handle is verified from a source. Never guess a handle.
- Sponsored threads say "Unlocked by @[sponsor]" in the first and last post.
- Charts: two or three at most per thread, 16:9, each with a source and date in the image or the post.

## Content rules

- **The hook carries the thread.** Post 1 states the most interesting finding and must stand alone if quoted. Never open with "In our latest report" or "We published...".
- **Lead with insight, then the number.** "Telcos are quietly routing traffic onto the network" before "burn doubled to ~$361K/month".
- **Every metric has context.** "$500M TVL, up 3x since January", not "$500M TVL".
- **Pick five to seven points.** A report thread is a trailer, not a summary of every section.
- **Include the risk.** A "What to watch" post with risks and catalysts belongs in every analytical thread.
- **Don't invent facts.** Every number and claim traces to the source report or notes. If something is missing, flag it rather than filling it.
- **End on the takeaway.** Report threads close with the link to the full piece. Insight threads close with a "Net-net:" line, not a sales pitch.

## Workflow

1. Read the source material: the report, notes or data the user provides.
2. Pick the type and the five to seven points worth posting.
3. Draft the hook three ways and keep the strongest.
4. Write the thread using the template.
5. Run the editor checklist below. Fix every issue and re-run until it's clean.
6. Run the stop-slop skill on the draft.
7. Hand over the thread, plus a short list of every number with its source so the user can spot-check.

## Editor checklist

Report each item as PASS or FAIL with a line of explanation for any FAIL.

**Structure**

- [ ] Post count is in range for the type.
- [ ] Posts are numbered.
- [ ] Post 1 is a standalone hook.
- [ ] The last post has the link (report thread) or a "Net-net" takeaway (insight thread).
- [ ] A risks or "what to watch" post is present.

**Format**

- [ ] One sentence per line, blank line between.
- [ ] Every post fits the character limit.
- [ ] Sponsored disclosure in the first and last post if sponsored.

**Content**

- [ ] Every fact traces to the source.
- [ ] Every metric has a base, comparison or date.
- [ ] @handles are verified.

**Style**

- [ ] Terminology and numbers follow `style.md` (onchain, no $ before tickers, compact units).
- [ ] No em or en dashes.
- [ ] No hype words, no exclamation marks, no rhetorical questions.
- [ ] Passes stop-slop.
