# Intro requests

Source: https://auren.substack.com/p/how-to-ask-for-an-introduction-the

An intro request has one acceptable form: a short, clear email that the connector can forward as is, and that leads to a double opt-in. Each person agrees before being connected.

Two people have to come out ahead:

- **The target** (the person the user wants to meet) must actually want the meeting. Name what they get from it.
- **The connector** (the person making the intro) wins only if both sides are happy. A lopsided intro costs the connector credibility and damages the user's relationship with them.

If the target gets nothing out of it, say so and stop before drafting. Ask the user what the target would gain. A polished email cannot fix a request with nothing in it for the target.

## The five steps

1. **Ask**: the user emails the connector.
2. **Forward**: the connector forwards that email to the target with a short note.
3. **Reply**: the target says yes (or nothing).
4. **Connect**: the connector introduces both people on one thread.
5. **Schedule**: the user replies quickly and books the meeting.

The user writes steps 1 and 5, and step 2 when they are the connector.

## Step 1: the ask

### Collect before drafting

- The target's name, title and company, plus their **LinkedIn URL**. The connector may not know which person the user means.
- The connector and how well the user knows them.
- **Why the target benefits.** It has to be concrete: shared customers, a deal, useful feedback, a hire, capital, a specific insight. "Would love to pick their brain" does not count.
- The user's credentials: role, company, one credible proof point, and the user's own LinkedIn URL.
- Logistics: why now, a city and dates if meeting in person.

Never invent facts such as customer names, metrics or bugs found. If something is missing, put a `[placeholder]` in the draft and list what the user still needs to fill in.

### Draft

```
Subject: intro to <Target Name> – <topic in 2–4 words>

<Connector first name>: can you intro me to <Target Name> (<LinkedIn URL>), <title> of <Company>?

<1–2 sentences on why the target benefits, with concrete specifics.>
<Optional: 1 sentence of extra value or proof.>

<Logistics, e.g. "I'll be in SF the week of the 14th and would love to meet.">

<User name> (<LinkedIn URL>)
<Title>, <Company>
```

Rules:

- **Subject** names the target and the topic. Never "quick question" or "intro?".
- **Around 100 words or fewer** in the body. People read these on their phones.
- **Write it to be forwarded.** The target will read every word, so keep out anything the user would not want them to see: flattery aimed at the connector, "I know he's hard to reach", negotiation tactics, internal context.
- **One target per email.** For several intros, write a separate email for each so each one can be forwarded.
- **Email only.** If the user plans to send it by LinkedIn DM, text, WhatsApp or X, recommend email instead, because those messages can't be forwarded. If text is the only way to reach the connector, a text pointing to the email is fine ("just emailed you about an intro to X").
- Don't ask for intros to famous or very in-demand people unless the user brings them something real.

### Critique checklist (when reviewing the user's draft)

- [ ] Would the target want this meeting? Is the reason specific?
- [ ] Does the connector look good forwarding it?
- [ ] The subject line names the target and the topic
- [ ] The target's LinkedIn URL and the user's LinkedIn URL are both included
- [ ] The user's credentials are visible
- [ ] Short, one target, readable on a phone
- [ ] Sent by email, and can be forwarded without edits

## Step 2: the forward (the user is the connector)

The connector filters requests and does not work for the person asking. Forward only when the target clearly benefits. Ask the target first; never cc both sides cold.

```
Subject: FW: intro to <Target> – <topic>

<Target first name>: want an intro to <Requester> (<LinkedIn URL>)?

<One line on why they're worth meeting.>

---------- Forwarded message ----------
<original ask>
```

If the target says yes, introduce them to each other on one thread. If the request is weak, help the user decline politely, or send it back to the requester with the fixes it needs.

## The follow-up

If there's no reply after about a week, send **one** follow-up, as a reply on the same thread. Never send a second one.

```
<Connector>: bumping this in case it got buried. Happy to tweak anything if it'd help.
```

## Step 5: the schedule ask

Getting the intro does not mean getting the meeting. When drafting the reply:

- **Reply within hours.** If it's already been days, open with a short apology.
- **Move the connector to bcc**, and say so on the first line: "Thanks <Connector> (moving you to bcc)."
- **Offer 4–5 specific times** with a time zone, and invite them to bring in an assistant or send their own scheduling link.
- **The user does the chasing**, so don't lead with the user's own Calendly. If the user insists, include it only after the specific times, as a backup option.
- **Don't act busy.** The user asked for this meeting.
- **Check timing.** Don't propose times right before the user's vacation or a known busy stretch. Ask about dates if they're unknown.

```
Thanks <Connector> (moving you to bcc).

<Target first name>: great to e-meet. <One line restating why it's worth their time.>

Would any of these work for <30 min / coffee>?
- <Day, date, time–time TZ>
- <...>  (4–5 options)

Happy to work with your assistant or use your scheduling link if easier.

<User name>
```

## Output

Give the user the email ready to paste: the subject line, then the body. Below it, add at most three short notes: placeholders they still need to fill in, a weak reason for the target to care, or a wrong channel or timing. Don't add any other commentary.
